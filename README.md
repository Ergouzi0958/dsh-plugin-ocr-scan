# 扫描件转 Markdown · DeepSeek Harness 插件

把一叠书页照片拖进对话框，插件帮你把它变成一份**能搜、能复制、能直接导进 Obsidian 的 Markdown 文档**，而且页序是自动排好的。

这是给 [DeepSeek Harness](https://github.com/deepseek-ai) 用的插件。

---

## 它解决什么问题

扫描一本书最烦的不是认字，而是**认完之后的一堆烂摊子**：

| 麻烦 | 不处理会怎样 | 本插件怎么做 |
|---|---|---|
| 扫描页顺序是乱的 | 195 页后面接 198 页，读起来前言不搭后语 | 从页眉读出印刷页码，自动排序 |
| 页眉页脚混进正文 | 每页都冒出「第九章 轴系零部件 ·195·」 | 按位置剥掉 |
| 标题和正文粘连 | `## 第一节 轴和轴毂连接轴是组成机器的重要零件…` | 自动拆开、分层级 |
| 表格渲染不出来 | Markdown 里全是竖线，Obsidian 不当表格 | 补分隔行、对齐列数 |
| 段落挤成一坨 | 几段话粘成一大段 | 自动补空行 |
| 插图丢失 | 只有文字，图全没了 | 每页原图一起存进 `images/` |

**一句话**：它不只做 OCR，它把 OCR 出来的散字重新拼回一份像样的文档。

## 快速开始

### 安装

1. 下载本仓库（点右上角绿色 **Code → Download ZIP**）
2. 打开 DeepSeek Harness → **Plugins（插件）→ Add plugin（添加插件）**
3. 选中解压后的文件夹

### 使用

1. 在聊天输入框下方找到一条窄条：**「⇪ 扫描件转 Markdown」**，点开
2. 把页面图片拖进去，或者按 `Ctrl+V` 粘贴截图
3. 填三样东西：
   - **书名** —— 会作为 Markdown 的一级标题
   - **模型** —— 默认混元 OCR，可切换
   - **API Key** —— 你的模型服务商密钥
4. 点 **开始识别**
5. 完成后，输出目录里会有：

```
我的书/
├── 我的书.md              ← 正文，每页配一张原图
├── 原书页-图册.md          ← 纯图册，按页翻
└── images/
    ├── page-194.jpg
    ├── page-195.jpg
    └── ...
```

把这个文件夹整个拖进 Obsidian 就能看了。

## 关于自动排序（这是重点）

扫描件**不能按文件名排序**。实测一本教材的真实扫描顺序是这样的：

```
文件名 (3) = 第 196 页
文件名 (2) = 第 195 页   ← 相邻两页被互换了
```

按文件名排，整本书就是乱的。

插件的做法：

1. 页码印在页眉两端（**偶数页在左，奇数页在右**，形如 `·195·`）
2. 浏览器把每页页眉的左右两端各裁一块、放大 3 倍
3. 问模型「这上面印的页码是多少？只回数字」
4. **只接受纯数字** —— 模型经常把别处认成 `件`、`The number 1`，这些一律丢掉
5. 按页码排序后，再用正文重合度检查相邻页是否真的接得上

> 小册子、讲义这类**没有印页码**的资料，只能退回按扫描顺序处理。这是硬限制。

## 可选模型

面板里有三个预设，也能填任何** OpenAI 兼容**的 `chat/completions` 接口。

| 名称 | model id | 特点 |
|---|---|---|
| 混元 OCR（默认） | `xophunyuanocr` | 标题层级自己就分好了，稳定，不失控 |
| PaddleOCR-VL | `xoppaddleocrv16` | 认出的字更多，但遇到插图散字会失控 |
| DeepSeek-OCR | `xopdeepseekocr` | 原生输出带版面标记 |
| 自定义 | 随便填 | 填模型 id + 接口地址，接任何兼容服务 |

**API Key 有三种填法**，任选其一：

1. 在面板里直接填（随请求发送，不写到磁盘）
2. 插件设置里的 `apiKey` 字段
3. 环境变量 `OCR_SCAN_API_KEY`

## 实测数据

用一本 36 页的《机械工程基础 · 第九章》扫描件测试：

| 项目 | 结果 |
|---|---|
| 识别耗时 | 约 2.5 分钟 |
| 章节标题 | 5 节 + 8 个小节，层级全对 |
| 表格 | 9 张，全部正常渲染 |
| 图注 | 37 条 |
| 页序 | 乱序扫描件还原成连续的 194–229 页 |
| 典型错字 | 曲蚰、稔定、GCr 巧、图 9 引 → 全部为 0 |

## 需要知道的限制

说得直白一点，免得你踩坑：

1. **要联网**。页面图片会上传到模型服务商。受版权保护或内部资料，请先确认能不能传。
2. **OCR 还是会认错字**。比如「巧」常常是数字 5，「佣」常常是 00。插件修不了模型本身的错，需要人工过一遍。
3. **速度不算快**。逐页识别，40 页大约 2–4 分钟。
4. **只给整页图，不单独抠插图**。试过按图注自动裁图，实测准确率不够（图注常被认成「图 9 一 7」「图 9 名」），宁可整页给你，信息一个不丢。
5. **面板挂在输入框下方**，默认收起成一条窄条，不挡聊天。

## 常见问题

**Q：点了开始没反应？**
检查 API Key 有没有填，接口地址是否正确。

**Q：页码没排对？**
这一页可能本身没印页码。翻翻原图确认；实在没有就只能手动调整。

**Q：表格还是不对？**
有些表格是**画在插图里的**，OCR 只能读到零散文字。这种情况看 `images/` 里的原页图最稳妥。

**Q：能离线用吗？**
不能。当前版本必须调云端模型。本地 Windows OCR 的方案在 `docs/DETAIL.md` 里有说明，但没有集成进这个插件面板。

## 开发者

插件分两半：

- `index.js` —— 宿主侧：调模型、排序、生成 Markdown，注册三个 HTTP 路由
- `client.js` —— 浏览器侧：拖放面板、模型选择、进度显示

```bash
node --check index.js
cp client.js /tmp/c.mjs && node --check /tmp/c.mjs
```
